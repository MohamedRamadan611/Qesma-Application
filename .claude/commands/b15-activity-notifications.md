Read AGENTS.md, **docs/PHASE2_SPEC.md sections 3 (group_events, notifications), 8, 10, 11**, docs/PROJECT_PHASES.md 2.7-2.8, Decision Log A65+, the existing `ExpenseService`, `ExpenseRevisionStore`, `SettlementService`, `MemberService`, `InviteService`/`JoinService`, `IdempotencyCleanupJob`, `SchedulingConfig`. Prerequisite: B14 merged. Skills (max 4): think-before-coding, data-modeling-discipline, query-discipline, observability-by-default.

Step 0 (plan, wait for approval): the six-step design, and settle (Decision Log):
1. **Atomic emission.** Events and notifications are written in the **same transaction** as the business write (no queue, no outbox worker, no push here). Define one `GroupEventRecorder` used by services (not by controllers); show for every existing write path (expense create/update/delete, settlement create/confirm/dispute/cancel, member joined/left/role changed, ownership transferred, join requested, invite accepted) the exact call site. A rollback must leave no event (test).
2. **Payload rule.** ids, versions and integer amounts only; **no names or titles stored** in `payload`. Names/titles are resolved at read time (so renames and account deletion stay consistent and logs/DB hold no extra personal data). Define the response shape: `{id, type, actorMemberId, createdAt, payload, subject}` where `subject` is the expense title resolved by the server when the expense still exists.
3. **Recipients.** Per type (PHASE2_SPEC section 8): derive from participants/payers with accounts, exclude the actor, exclude LEFT members and unlinked ghosts, dedupe. For an edit, notify the union of the old and the new participant sets (use the revision data). Large groups: bound the fan-out (max 100 members per group already) and use one batched insert.
4. **Read APIs.** `GET /groups/{gid}/activity?limit&before` and `GET /notifications?limit&before` with **keyset** pagination on `(created_at, id)` (max 50), `GET /notifications/unread-count`, `POST /notifications/read {ids|all}` (only the caller's own rows; unknown/foreign ids ignored silently? decide: recommended count only owned). Index design with `explain-this-query` evidence for both lists and the unread count (partial index on `read_at IS NULL`).
5. **Permissions and privacy.** Activity: any ACTIVE member reads their group's feed; a member who joined later sees events from the join date only? (decide; recommended: the whole feed, it is group history). Notifications are strictly per user.
6. **Retention and observability.** Scheduled purge of events/notifications older than 180 days (same pattern as `IdempotencyCleanupJob`), counters for events written per type, no payload logged.

Implement: migration V16 (`group_events`, `notifications` with indexes), entities, repositories, recorder, retrofit all write paths, read services/controllers/DTO records, purge job, OpenAPI + operation ids, DevSeed (a few events), README, Decision Log.
Tests (Testcontainers): one test per event type asserting the feed row, recipients and non-recipients (actor excluded, left member excluded, ghost excluded); edit notifies old and new participants; rollback atomicity (force a failure after the event insert); keyset pagination stability with equal timestamps; unread-count and mark-read (own rows only, IDOR on another user's notification ids); feed authorization matrix (member 200, stranger 404, LEFT 404); payload contains no names (assert the stored JSON); statement-count test for fan-out (recipients resolved with one query and the notification rows written with one batched insert/`saveAll`, constant statements for 2 vs 100 recipients; `hibernate.jdbc.batch_size` is already 50 in `application.yml` but `order_inserts` is not set: add `hibernate.order_inserts=true` or use one multi-row `INSERT`, and verify the statement count with Hibernate statistics) and for listing (feed/center resolve `subject` titles and member names with one batched query per page); purge job; B10 matrix extended.
Constraints: follow AGENTS.md; no new dependency; no push (B18); no real-time sockets; do not change money behaviour of existing endpoints. Done when `./mvnw clean verify` passes. Then Stop protocol; tell the owner `mobile` must regenerate the client.
