Why this exists: the screen designs need to know **which member is the signed-in user** ("(you)", "you are owed / you owe" per group, "your share" per expense) and the generated Dart client needs a **truthful OpenAPI**. Both are backend changes; do them before `fl3`.

Step 0 (plan, wait for approval): the six-step design, and settle these decisions explicitly in the plan (record each in the Decision Log from A53 on, and amend spec 3.1/6 where it says members are ghosts and `user_id` is null in Phase 1):
1. **Owner member.** Creating a group also creates member #1 for the owner (`members.user_id` = owner, name = the user's display name cut to 40 code points, fallback "Me"), in the same transaction as the group. Decide: rename allowed (recommended); **delete** of that member: block with a stable error (recommended: 409 with a NEW code, e.g. `OWNER_MEMBER_PROTECTED`, added to ErrorCode, OpenAPI `Problem` enum and `ApiContractCoverageIT`) vs allow; interaction with group delete (members are hard-deleted with an empty group, A23) and with `member_seq`/`sort_order`.
2. **Existing groups** (created before B9): data migration `V9__...` that adds the owner member to groups lacking one (sort_order = member_seq + 1, bump member_seq), or no backfill (acceptable only if no real data exists: ask the owner). Never edit V1-V8.
3. **API shape.** `MemberDto.isYou` (true when `user_id` = caller); `GroupDto.yourMemberId` (nullable for legacy groups); `yourNetMinor` (nullable long, "positive = you are owed") on `GroupSummaryDto` and `GroupDto`.
4. **`yourNetMinor` computation** without N+1: one grouped statement per page of groups (reuse the idea of `BalanceTotalsQuery`: per-(group, member) paid/owed/sent/received sums for the caller's linked members, one snapshot), the formula in the pure engine (extend `BalanceCalculator` with a single-member net, same `Exact` arithmetic; unit + property tests that it equals `netsFromTotals` for that member). Null when the group has no linked member. Query-count test: constant statements for 1 vs 50 groups. Note in the OpenAPI description that amounts of different group currencies must not be added by clients.
5. **OpenAPI status fidelity.** `docs/openapi.json` declares `200` where the code answers `201`/`204` (`POST /groups`, `POST .../members` are 201; `DELETE .../expenses/{eid}` and `DELETE .../settlements/{sid}` are 204). Fix the annotations/`OpenApiConfig`, document the `Location`, `ETag` and `Idempotency-Replayed` response headers, and extend `ApiContractCoverageIT` so that for every operation the **real** success status must equal a status declared in the generated document (a test that would have caught this).

Implement: migration (if chosen), `GroupService.create` (+ owner member), `MemberService` rule, DTOs and mappers, the totals query + engine method, OpenAPI fixes, regenerate `docs/openapi.json` (`-Dopenapi.write=true`), update `DevSeedRunner`/`DevSeedIT` (the owner is now member #1 "محمد": the seed adds the other four, same documented balances), README curl examples, Decision Log, `docs/mobile-client.md` if the command changes.

Tests (Testcontainers): group creation yields exactly one linked member with `isYou=true`; rename allowed; delete of the owner member follows the decided rule; delete empty group removes it; group with expenses still 409; `yourNetMinor` correct on the V1-style scenario (owner as M) and null for a legacy group; settlements and expense edits/deletes move it; 50-group list statement count constant; IDOR matrix and mass-assignment tests unchanged and green (a client cannot set `isYou`/`userId`); OpenAPI drift test updated; contract status test. Existing tests may change only where the owner member legitimately changes their expectations: list each changed assertion in the summary and never weaken one.
Constraints: follow AGENTS.md; no new dependency; do not touch the engine's split rules or fixtures; Phase 1 scope only (no invitations, no roles). Done when `./mvnw clean verify` passes. Then follow the Stop protocol and tell the owner that `mobile` must regenerate the client (`docs/mobile-client.md`) because the contract changed.
