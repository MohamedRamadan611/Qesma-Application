Prerequisite: FL4 merged. Skills (max 4): think-before-coding, ui-ux-pro-max, ux-copy, accessibility-review.

Step 0 (plan, wait for approval), the six-step client design with these points answered explicitly: (1) the form state model and how it becomes an `ExpenseCommand` (a pure function with golden JSON tests); (2) **preview**: every number shown per member comes from `POST .../expenses/preview` (debounce 300 ms, cancel or ignore out-of-order responses, show a subtle loading state, never show a stale preview as current); (3) the **idempotency key lifecycle** with `IdempotentAction`: key created on the first save tap, reused on every retry while the body is unchanged, replaced when the user edits the form after a failed attempt, cleared on success; what the user sees when the response was lost (retry button, same key, expect `Idempotency-Replayed`); (4) edit mode: `PUT` with `If-Match` and an **explicit participant list** (never rely on "all" when editing: spec 7.9), conflict dialog that reloads the latest version and keeps the user's input; (5) which design elements are omitted (receipt photo, emoji in the title, per-member captions); (6) the ITEMIZED tab is shown but leads to FL6 (stub until then, behind a clearly marked route).

Implement:
1. **Add/edit expense** (P5-01): title (max 100), amount (EGP text -> piasters via `core/money`, max 10^12), date (default today, 2000..2100), paid-by summary row, split tabs **All / Selected / Exact amounts / Restaurant bill**, member rows with checkboxes and the per-member amount from preview, "remaining" banner for Exact (allowed arithmetic: the sum of amounts the user typed versus the total), save button disabled until the form is valid and, for Exact, the sum matches.
2. **Paid-by editor** (P6-01): select payers, enter amount per payer, running "remaining" indicator (sum of typed amounts versus total; must reach zero), `payersTotalMatches` from preview as the authority, a **"split equally among selected payers"** action that calls preview (EQUAL, participants = selected payers) and copies `members[].owedMinor` into the payer amounts (no client division), clear amounts, confirm.
3. **Exact tab prefill**: choosing Exact prefills each selected member with the EQUAL preview result (server numbers), then the user edits.
4. Save: create with `IdempotentAction`; on 201 go to the details page (FL4); inline errors by code (`PAYERS_TOTAL_MISMATCH` banner on the payers sheet, `SPLIT_TOTAL_MISMATCH` on the split section, `MEMBER_NOT_IN_GROUP` reload members, `VALIDATION_ERROR` under the field); offline keeps the form.
5. Edit: load from `GET`, same screens, `PUT` with `If-Match`.

Tests: `ExpenseCommand` builder golden JSON for EQUAL all (field `participantMemberIds` omitted on create, explicit on edit), EQUAL selected, EXACT; preview debounce and stale-response tests (fake async); key lifecycle tests (retry reuses, edit regenerates, success clears, 409/422 behaviour); remaining-indicator tests (typed sums only); prefill-from-preview tests; amount parsing edge cases (0, 0.5, 1,000.50, Arabic digits, over the cap); conflict dialog flow; widget tests ar/en/text scale 2.0; golden for the form and the payers sheet; guard tests.
Constraints: SCREEN_MAP rules (no split math, no "half" buttons, no client rounding); do not build ITEMIZED here. Done when analyze and tests pass. Then Stop protocol; do NOT start FL6 here.
