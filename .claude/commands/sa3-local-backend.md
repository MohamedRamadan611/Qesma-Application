Read AGENTS.md, mobile/AGENTS.md, docs/STANDALONE_SPEC.md (local backend rules, endpoint list), ADR-011, docs/PROJECT_SPEC.md sections 7-8 (all), docs/PHASE2_SPEC.md sections 3, 6 and 10, `docs/openapi.json`, and the Java services to port: `GroupService`, `MemberService`, `ExpenseService`, `ExpenseValidator`, `ExpenseCalculator`, `EngineErrors`, `SettlementService`, `SettlementValidator`, `BalanceService`, `FieldRules`, `IdempotencyService`, `ExpenseGroupUsageChecker`, `ExpenseMemberUsageChecker`, `api/ErrorCode.java`, the Problem JSON shape. In mobile: `lib/core/auth/auth_providers.dart` (`httpAdapterProvider`), `lib/core/api/` (`etag_store`, `idempotent_action`), `lib/core/errors/`, every `features/*/data/*_repository.dart` (to list the operations really called), and `test/support/fake_*_server.dart` (the in-process pattern to follow). Prerequisite: SA2 merged. Skills (max 4): think-before-coding, idempotency-and-side-effects, error-handling-as-design, testing-with-discernment.

Step 0 (plan, wait for approval): (1) the exact operation list served in local mode (method, path, request/response DTO, status codes, errors) taken from the repositories, and the list of operations deliberately answered with `404 NOT_FOUND` in local mode (invites, join requests, notifications, remind, account deletion, auth endpoints); (2) router design: path matching, JSON (de)serialization with the generated `qesma_api` serializers so responses are byte-compatible with the server's DTOs; (3) service layer in `lib/local/service/` ported from Java, each write in one drift transaction together with its idempotency record and revision; (4) ETag/`If-Match` and `VERSION_CONFLICT` with `currentVersion` and latest state (B17 shape); (5) settlements: created CONFIRMED, cancel allowed, no confirm/dispute in local mode; balances use CONFIRMED only; (6) the local identity: one local user, `GET /me` from `local_profile`, the "you" member #1 created with each group (B9 rule), role OWNER everywhere; (7) errors: every engine/validation failure becomes the same Problem JSON `code` and HTTP status as the server; unexpected exceptions become `500 INTERNAL_ERROR` without stack traces, and are not swallowed (logged by id only).

Implement:
1. `lib/local/backend/local_backend.dart` (`LocalBackend implements HttpClientAdapter`), `lib/local/backend/router.dart`, `lib/local/service/*` (groups, members, expenses incl. preview and revisions, settlements, balances, me/profile, own payment handles), `lib/local/errors.dart`.
2. A provider override helper `localBackendOverrides(LocalDatabase db)` (used by SA4) — do not change `main.dart` yet.
3. Guard update: money math allowed in `lib/local/service/` (only through `qesma_engine` calls and plain sums of stored amounts), still banned in `lib/features/**`.

Tests: a **conformance suite**: run the existing repository and feature tests (groups, members, expenses, itemized, balances, settlements) with `httpAdapterProvider` overridden by `LocalBackend` over an in-memory DB instead of the fake servers — list which tests run in both modes and which are server-only; engine fixture scenarios V1-V8 reproduced end-to-end through the HTTP contract (create expenses + settlements, then `GET balances` equals the fixture nets and transfers); idempotency (same key + same body -> same response with `Idempotency-Replayed`; same key + different body -> `IDEMPOTENCY_KEY_REUSED`); `If-Match` stale -> 409 with latest state; group delete blocked when not empty; member delete blocked when used (including soft-deleted and owing-0 assignee cases); duplicate Arabic member names; limits at 10^12 and 100 items; atomicity (a failure mid-write leaves no partial rows); local-mode-only 404s for server-only endpoints.
Constraints: the contract is `docs/openapi.json` — do not invent fields; do not edit `packages/qesma_api`; integer money only; no UI changes. Done when analyze and all tests pass (both modes). Then Stop protocol; do NOT start SA4.
