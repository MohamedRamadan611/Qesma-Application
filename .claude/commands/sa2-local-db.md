Read AGENTS.md, mobile/AGENTS.md, docs/STANDALONE_SPEC.md (data rules, backup), ADR-011, ADR-012 (drift, drift_dev, build_runner, `sqlite3` 3.x and path_provider versions; `sqlite3_flutter_libs` is end-of-life and NOT used), docs/PROJECT_SPEC.md sections 6 and 7.9-7.10, Decision Log A13-A24, A42-A47 and A121+, and the Flyway migrations `backend/src/main/resources/db/migration/V4`-`V9`, `V12` (role/status), `V15` (settlement status), `V16` (payment handles). Prerequisite: SA1 merged. Skills (max 4): think-before-coding, data-modeling-discipline, migration-safety, testing-with-discernment.

Step 0 (plan, wait for approval): the six-step design with: (1) the table list and every column, type, CHECK, UNIQUE and FK, mapped one by one to the Postgres original (say what is dropped because it is server-only: users, refresh tokens, passwords, invites, join requests, events, notifications, remind log; what is new: `local_profile`, `local_meta(schema/export version)`); (2) money and bps as INTEGER, ids as TEXT UUID, timestamps as UTC ISO-8601 TEXT or integer epoch millis (choose one and justify), dates as `YYYY-MM-DD`; (3) `member_seq` per group and the unique `(group_id, lower(display_name))` (SQLite `lower()` is ASCII-only: explain how Arabic names are compared — recommended: store a normalized `name_key` column filled by one Dart function and put the UNIQUE on it); (4) soft delete, versions and immutable revision snapshots (JSON text); (5) the idempotency table (key, request hash, response snapshot, created_at) and its retention; (6) drift schema versioning: `schemaVersion`, step-by-step migrations, exported schema snapshots and generated migration tests; database file location and Android auto-backup inclusion; (7) foreign keys ON (`PRAGMA foreign_keys`) and WAL.

Implement:
1. Add the ADR-012 dependencies (exact versions) to `mobile/pubspec.yaml`; `mobile/lib/local/db/` with the drift database, tables and DAOs (groups, members, expenses, payers, splits, items, assignees, revisions, settlements, payment handles for the local profile only, idempotency keys, local profile, meta).
2. A `LocalDatabase` provider (`lib/local/db/local_database_provider.dart`) opening the file in the app documents directory; an in-memory constructor for tests.
3. Narrow `source_guards_test.dart` path rules so `lib/local/` may hold persistence code (no money math yet — that arrives with SA3), as listed in SA0's guard change list.

Tests: schema tests in memory: every CHECK/UNIQUE/FK rejects a bad row (negative amount, amount > 10^12, bps > 10000, duplicate member name in Arabic and English with different case/spacing as normalized, settlement from = to, orphan payer); revisions are append-only (DAO has no update/delete for them); soft-deleted rows stay readable for history; migration test from schema v1 snapshot to current; a DAO round-trip for one full itemized expense. Make the tests run on the Windows dev machine (document how the native sqlite library is provided for `flutter test`).
Constraints: no business rules in DAOs (those are SA3 services); no UI changes; forward-only migrations; never log names or titles. Done when analyze and tests pass. Then Stop protocol; do NOT start SA3.
