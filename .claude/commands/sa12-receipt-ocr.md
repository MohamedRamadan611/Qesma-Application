Read AGENTS.md, mobile/AGENTS.md, `.claude/mobile/SCREEN_MAP.md`, docs/STANDALONE_SPEC.md (receipt OCR) and Decision Log entries, ADR-012 (firebase_core, firebase_ai, firebase_app_check, image_picker versions), `lib/core/money/money.dart` (`Money.parse`, `Bps.parse`), `lib/features/expenses/` itemized editor (FL6) and its state model, `test/guards/scope_guard_test.dart` and `source_guards_test.dart`. Read the **current** Firebase AI Logic and App Check documentation for Flutter before Step 0 (setup steps, model id of the current Flash-Lite model, structured output / response schema, free-tier conditions, error types for quota and permission) and quote what you rely on. Prerequisite: SA11 merged. Skills (max 4): think-before-coding, security-discipline, error-handling-as-design, ux-copy.

A 20-item restaurant bill is unusable by hand; this is a launch feature. The AI only **proposes**; the user confirms every number.

Step 0 (plan, wait for approval): the six-step design with: (1) setup: Firebase project on the Spark plan (no billing account), Gemini Developer API backend, App Check with Play Integrity (debug provider for dev builds), what the owner must do in the Firebase console (list it as human steps), `google-services.json` handling (not a secret, but not changed by hand); (2) capture: `image_picker` camera or gallery, downscale/compress before upload (state max size and quality), EXIF/location stripped, nothing written to permanent storage, no logging of the image or the response; (3) request: prompt + JSON response schema: `items[{name, amount}]`, `subtotal`, `servicePercent`, `serviceAmount`, `taxPercent`, `taxAmount`, `total`, `currency`, all amounts as strings; Arabic and English receipts, Arabic-Indic digits; (4) parsing: every string through `Money.parse`/`Bps.parse`; items that fail parsing are kept with an empty amount and flagged; never trust the model's arithmetic; (5) draft: open the itemized editor (FL6) as an **unsaved draft** with items, service/tax toggles and percents; the user assigns members; banner when the parsed items + charges do not match the printed total (from the editor's existing preview, not client math); (6) consent: a one-time screen before the first scan (what is sent, to whom, free-tier data use, how to avoid it: type manually), stored locally, revocable in the profile; (7) failure modes, each with its own Arabic message and a "type manually" action: offline, timeout, quota exhausted, App Check/permission denied, unreadable photo, model returned invalid JSON; a per-device daily cap (number from STANDALONE_SPEC); (8) the "OCR disabled" remote switch is out of scope — instead the feature hides itself after repeated permission errors (decide).

Implement: Firebase initialization (local mode only), `lib/features/receipt_scan/` (capture, consent, client service behind an interface `ReceiptReader` so tests use a fake, parser, draft mapper), entry point "Scan receipt" in the itemized editor and the expense FAB menu, ARB strings, narrowed dependency ban (allow exactly firebase_core, firebase_ai, firebase_app_check; analytics/crashlytics stay banned), scope guard: unlock receipt/scan/camera words and icons for this feature only, privacy policy draft text for SA13.

Tests: parser tests with recorded model responses (fixtures under `test/fixtures/receipts/`: Arabic receipt, English receipt, Arabic-Indic digits, service + tax, tax only, missing total, garbage JSON, extra fields, negative/huge amounts); draft mapper golden (draft -> itemized editor state); failure-mode tests with the fake `ReceiptReader` (each error -> right message + manual action; daily cap); consent flow tests; widget tests ar/en/text scale 2.0; guard tests; a test that nothing image-related is written outside the temp directory. Manual (human) checks recorded in `docs/gates/`: 10 real Egyptian receipts on a real phone with accuracy notes.
Constraints: no API key in the app or the repo; no image storage; no auto-save; integer money only; no other new dependencies. Done when analyze and tests pass and one real scan works on the phone. Then Stop protocol; do NOT start SA13.
