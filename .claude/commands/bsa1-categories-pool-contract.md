Step 0 (plan, wait for approval): the six-step design and settle (Decision Log): (1) `expenses.category` (text enum FOOD, TRANSPORT, FUEL, ACCOMMODATION, GROCERIES, SHOPPING, ENTERTAINMENT, BILLS, OTHER; NOT NULL DEFAULT 'OTHER', CHECK), in `ExpenseCommand` (optional, default OTHER), `ExpenseView`, list filter `?category=`, and in the revision snapshot; (2) `expense_groups.treasurer_member_id` (nullable FK to an ACTIVE member of the same group) set via `PATCH /groups/{gid}` with `If-Match`; change allowed only when no pool deposit and no pool expense exists (`409 INVALID_STATE_TRANSITION` or a new code — decide and add to `ErrorCode`, OpenAPI enum and `ApiContractCoverageIT`); (3) `expenses.paid_from_pool` boolean NOT NULL DEFAULT false, valid only when the group has a treasurer and the expense has exactly one payer who is the treasurer (`VALIDATION_ERROR` otherwise); (4) `settlements.kind` PAYMENT | POOL_DEPOSIT (NOT NULL DEFAULT 'PAYMENT'); a POOL_DEPOSIT must go to the current treasurer; balances treat both kinds identically (prove nets unchanged by the kind); (5) pool meter `GroupDto.poolBalanceMinor` (null when no treasurer) = CONFIRMED deposits − non-deleted pool expense totals, computed in one query, never stored; (6) authorization: the same roles that may edit the group / record settlements (B10 matrix) — no new permission.
