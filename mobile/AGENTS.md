## Planned conventions (spec section 5.2)
- Flutter + Dart, Android first. State: Riverpod. Navigation: go_router. HTTP: dio with a client GENERATED from `docs/openapi.json` (never hand-write API models).
- Feature-first folders: `lib/features/{auth,groups,members,expenses,balances,settlements}`, `lib/core/`.
- Localization with ARB files (ar primary, en secondary); full RTL; Western digits (0–9) for amounts.
- Do NOT re-implement split/balance logic in screens, notifiers or repositories under `lib/features`: call the `preview` and `balances` endpoints. **Standalone release (ADR-011, STANDALONE_SPEC):** the Dart engine is `packages/qesma_engine` (validated against `../fixtures`), and **the local backend (`lib/local/`) is the only place outside `qesma_engine` and `core/money` where money math is allowed**, only through `qesma_engine` calls and plain sums of stored amounts. Screens still never compute splits, balances, the pool meter, My share or the recap. `package:qesma_engine` is imported only under `lib/local/**`.
- Design tokens: `../docs/design/DESIGN.md`. Screen images: `../docs/design/screens/` named by screen ID (e.g. `P7-04-itemized-service-and-tax.png`); open the exact file before implementing a screen.
- Online-only in server mode (clear error + retry when offline). Local mode (`QESMA_MODE=local`, standalone release) is offline by design; its settings and ledger live in the drift DB, not in `shared_preferences`.
